## 一、已取得成果（参加学术会议、学术沙龙和发表论文、申请专利、参加竞赛活动等详细情况）*必填

本阶段以**原型系统研发与关键技术验证**为主，同步开展组内学术沙龙与技术研讨，并启动软件著作权申请准备。中期已取得的阶段性成果如下：

1. **可运行的校园 App + 本地 AI Agent 联调原型**  
   完成基于 uni-app（Vue 3）的「鲤工助手」真机可运行版本，集成校园服务导航、WebVPN 深链网关、本地课表导入与展示、每日签到、立绘/Emoji 鉴赏，以及「华工智能体」对话页；后端 `00.my-agent` 采用 FastAPI + LangGraph ReAct + 大模型 + 向量知识库，实现 `POST /chat`、`POST /chat/reset`，并已完成 USB 调试 / `adb reverse` 真机联调。

2. **“对话即服务”核心能力阶段性验证（对应立项中的意图直达与工具调用）**  
   - **阶段一（对话驱动跳转）**：建立前后端统一的 `actions[]` 协议（`switch_tab` / `navigate_to` / `open_campus_web`），将查分、选课、教务、课表、立绘等封装为可调度服务目录；用户自然语言提问后，Agent 可返回可读回答并驱动 App 跳转，路径与首页按钮一致（含 WebVPN 先登录再进入）。  
   - **阶段二（本地课表上下文）**：按用户意图裁剪并上传 `device_context`（今日/相对日/本周/完整课表摘要、当日签到等），后端注入本轮提示，支持「今天有什么课」「下一节课」等问答，并约束模型**禁止编造**未提供的课程信息。  
   - **知识库问答**：完成华工相关文档向量化检索（RAG）与回复渲染（Markdown / 思考过程折叠、长按复制、新对话清会话）。

3. **工程与文档沉淀**  
   整理 Agent 自建与真机联调说明，后端配置模板与启动文档已对应开源仓库 [SCUT-Helper-Agent](https://github.com/tuoxingwanli/SCUT-Helper-Agent)；项目组内部完成架构说明与实现计划文档，为后续软件著作权材料整理与开发指南撰写打下基础。

4. **学术沙龙与技术研讨会议**  
   项目组定期组织内部学术沙龙与技术研讨，围绕校园 Agent 落地中的关键问题开展讨论与复盘，主要议题包括：大模型工具调用与 `actions` 协议设计、RAG 知识库构建与幻觉抑制、App 端动作执行与 WebVPN 深链体验、本地课表隐私边界与 `device_context` 意图裁剪、真机联调与部署方案等。通过研讨统一技术路线、明确阶段验收标准，并形成会议纪要与待办清单，保障跨学院成员协作推进。

5. **软件著作权（准备申请）**  
   已启动「鲤工助手 / 华工智能体」相关软件著作权申请准备：梳理软件全称与简称、功能模块说明、架构图与操作说明截图等材料，计划于后半阶段正式提交登记申请。

## 二、项目进展状况小结*必填

对照立项书「五个阶段」安排，截至中期检查，项目整体进度约 **50%**，与第二阶段收尾、第三阶段启动的时间节点基本吻合。

### （1）已完成工作

| 立项计划要点 | 中期实际进展 |
| --- | --- |
| 需求调研与技术选型 | 已完成高频场景梳理（导航、课表、查分/选课深链、校园问答）；确定「大模型 + 工具调用 + RAG + App 端执行器」路线；明确**不做 GUI 自动化**，优先 DeepLink/结构化动作与本地数据上下文。 |
| 知识库构建与基础对话 | 已搭建本地向量库与知识检索工具；App 智能体页可稳定对话、会话记忆（thread）、新对话重置、异常时引导自建后端配置。 |
| 校园服务封装与跳转 | 已完成服务目录前后端对齐；支持对话驱动打开课表 Tab、立绘/Emoji、WebVPN 校园服务等。 |
| 课表相关能力 | 已完成本地课表导入（WebVPN + WebView 注入提取）与周课表展示；Agent 可基于本地摘要回答当日/本周等课表问题。 |
| App 载体与体验 | 原生 tabBar 四主页（首页/智能体/用户/课表）、签到、立绘鉴赏等已可用，形成可演示的完整产品闭环。 |
| 研讨与知识产权准备 | 组内沙龙/技术研讨常态化；软著材料准备中。 |

### （2）与立项目标的对应关系（中期视角）

- **变革交互模式**：已从「仅按钮入口」扩展为「对话框 + 动作执行」双通道，验证了「一句话打开查分/选课/课表」等意图直达场景。  
- **整合碎片化信息**：已将导航深链、本地课表、签到状态、校园知识文档纳入统一 Agent 出口；贴吧/二手书/评课深度检索、后勤主动推送等仍属后半阶段。  
- **技术可行性**：已验证垂直场景下 ReAct 工具调度、`actions` 防连环跳转、意图裁剪上传以降低上下文与幻觉风险等关键机制。  
- **多端一致**：当前以 **App 真机为主**完成联调；H5/小程序同构能力具备基础，规模化多端同步与云端会话同步待后半阶段加强。

### （3）阶段性结论

中期已形成「**可演示、可联调、可扩展**」的校园 Agent 最小闭环：**懂一点华工（知识库）→ 能办事（跳转）→ 能读本地课表（上下文）**。距离立项预期的「二手书智能检索、通识课智能推荐、主动生活提醒」以及软件著作权正式登记等完整成果仍有一半工作量，进度整体可控。

## 五、项目存在问题及解决方案*必填

1. **校园业务系统开放接口有限，难以直接对接教务/后勤实时数据**  
   - **问题**：立项中的水电监测、成绩开放 API、二手书/评课全域检索等依赖官方接口，短期内难以全部打通。  
   - **对策**：坚持「能跳转先跳转、能本地先本地」——查分/选课等走 WebVPN 深链；课表以用户授权导入的本地数据 + `device_context` 问答；二手书/评课等先做知识库与半自动检索原型，接口成熟后再替换为正式工具。

2. **大模型幻觉与垂直场景准确性**  
   - **问题**：通用模型易编造课程、教室或政策细节。  
   - **对策**：课表类强制依赖设备上下文并禁止编造；政策类走 RAG；跳转类用白名单 catalog；后续建立评测用例与人工抽检机制，并在技术研讨中定期复盘失败案例。

3. **真机联调依赖本地后端与 USB 调试，部署形态偏「科研原型」**  
   - **问题**：正式包仍需自建 Agent 与 `adb reverse`（或不提供公共云端以免 Key 费用失控），距离「开箱即用」有差距。  
   - **对策**：完善开源一键启动与文档；中后期评估校园网/实验室小范围服务部署；在结题材料中明确部署边界与成本方案。

4. **会话记忆与多轮上下文一致性**  
   - **问题**：后端进程内记忆重启即失；多轮中可能残留旧课表上下文。  
   - **对策**：App 端提供「新对话」对齐；后半阶段增加记忆持久化与「仅保留最新 device_context」策略，并做 token/窗口裁剪。

5. **软件著作权申请与规模化内测尚未完成（中期正常）**  
   - **问题**：中期以工程验证与研讨为主，软著尚在材料准备阶段，志愿者规模化内测未启动。  
   - **对策**：按第三节时间表倒排：先固化演示材料与功能说明，尽快提交软著登记；内测与志愿者招募与第三、四阶段绑定，避免结题前突击。

6. **团队成员跨学院协作与进度同步**  
   - **问题**：分工涉及前端、Agent 后端、知识整理、测试与文档，沟通成本较高。  
   - **对策**：固定例会与沙龙研讨；任务看板跟踪；前后端服务目录双份维护改为「单源生成」；关键接口变更必须同步重启后端并回归真机用例。
