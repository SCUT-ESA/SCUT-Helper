# 鲤工助手 · 项目架构说明

本文档基于当前代码库梳理，描述「鲤工助手」的目录结构、页面职责、组件关系、数据存储与跳转链路，以及旁路的 **宣传动画板块**（`01.动画/`），便于后续开发与维护。

---

## 1. 项目概览

| 项 | 说明 |
| --- | --- |
| 产品名 | 鲤工助手 |
| 定位 | 面向华南理工大学学生的校园服务导航 + 课表工具 + 智能体问答 + 立绘鉴赏 |
| 技术栈 | uni-app 3.x + Vue 3 + Vite 5 + Sass |
| Vue 版本 | 3（`manifest.json` → `vueVersion: "3"`） |
| 应用 ID | `__UNI__9F214E5` |
| 版本 | `0.0.0` / versionCode `100` |
| App 开源仓库 | [https://github.com/SCUT-ESA/SCUT-Helper](https://github.com/SCUT-ESA/SCUT-Helper)（本仓库；原 `tianma-afk/SCUT-Helper` 已迁移至此） |
| Agent 开源仓库 | [https://github.com/tuoxingwanli/SCUT-Helper-Agent](https://github.com/tuoxingwanli/SCUT-Helper-Agent)（对应 `00.my-agent/`，不含 `.env`） |
| 宣传片（B 站） | [鲤工助手（专为华工er打造）](https://www.bilibili.com/video/BV11hKY6QETQ/)（`BV11hKY6QETQ`） |
| 旁路板块 | `01.动画/`：Manim 程序化 **App 宣传片**（非 App 运行时依赖；成片以上方 B 站链接为准） |

核心能力分为五块（App 内）：

1. **校园功能导航**：首页聚合常用/更多服务入口（Web / 小程序链接）；WebVPN 深链走「先登录再进入」
2. **每日签到**：按自然日一次；签到后展示随机华工助手 Emoji + 配语，并累计天数（已不再测运势）
3. **课表**：本地存储课表展示，App 端可从教务系统 WebView 注入脚本提取并导入
4. **华工智能体（Agent）**：知识库问答 + **对话驱动跳转**（校园服务 / 立绘等）+ **按意图注入本地课表与当日签到**（不做 GUI 自动化）；支持「新对话」清空前后端会话、长按复制气泡/思考过程；连不上本地后端时引导打开开源配置仓库
5. **立绘 / Emoji 鉴赏**：用户页入口；立绘页 5 卡跟手翻页（说明 → Emoji 入口 → 半身/全身/草图）；Emoji 页浏览 16 张表情原图 + 配语

另有独立旁路：

6. **宣传动画**（`01.动画/`）：黑底科技风 Manim 成片；叙事对齐现行产品（导航 + 签到 Emoji + 课表 + Agent + 立绘）；成片发布于 B 站：[鲤工助手（专为华工er打造）](https://www.bilibili.com/video/BV11hKY6QETQ/)；详见 [§12 宣传动画板块](#12-宣传动画板块)

## 2. 技术架构

```
┌─────────────────────────────────────────────────────────┐
│                    运行平台（多端）                        │
│   App-Plus / 微信小程序 / H5 / 其他小程序端 …              │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│              uni-app 运行时 + Vue 3 SSR App               │
│   main.js → createSSRApp(App) → pages.json 路由          │
└───────────────────────────┬─────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   页面层 pages/      组件层 components/    静态资源 static/
        │                   │
        └─────────┬─────────┘
                  ▼
        本地存储 uni.storage  /  外部 Web  /  登录 API  /  本地 Agent（:8000）
```

- **构建**：`@dcloudio/vite-plugin-uni`（见 `vite.config.js`）
- **入口**：`src/main.js` 导出 `createApp()`；`src/App.vue` 仅处理 `onLaunch` / `onShow` / `onHide`
- **路由与窗口样式**：`src/pages.json`（**原生 `tabBar` + `switchTab`**；首屏为首页）
- **应用与平台配置**：`src/manifest.json`
  - 应用图标：`distribute.icons` → `static/icons/*.png`（由 `07.icon.jpg` 生成）
  - 需**自定义基座 / 云打包**后桌面图标才生效；已**移除**自定义 Android Splash 图与首页冷启动遮罩（使用系统默认启动过程）
- **全局样式变量**：`src/uni.scss`
- **智能体后端**：本仓库内 `00.my-agent/`（FastAPI + LangGraph ReAct + MiniMax），App `POST /chat`、`POST /chat/reset`；真机需 **USB 调试** + `adb reverse tcp:8000 tcp:8000`（仅「传输文件」不够）
  - **不提供公共云端 Agent**：费用由自建者自备 API Key；开源说明与启动教程见 [SCUT-Helper-Agent](https://github.com/tuoxingwanli/SCUT-Helper-Agent)
  - App 连不上后端时：错误气泡展示可点击「查看后端配置说明」+ 完整 URL，点按经 `openCampusWeb` 打开该仓库 README
- **Agent 计划文档**：根目录 `Agent实现计划.md`（阶段一/二目标与验收；以源码为准）
- **宣传动画**：旁路目录 `01.动画/`（Manim；`ligong2.py` → `LiGongAssistant`）；与 App 解耦，详见 [§12](#12-宣传动画板块)

### 4.1 Tab 主框架（原生 tabBar）

使用 `pages.json` → `tabBar` + `uni.switchTab`（保活、避免旧版自定义 Tab + `reLaunch` 闪屏）。

| 顺序 | 文案 | 页面 | 图标 |
| --- | --- | --- | --- |
| 0 | 首页 | `pages/index/index` | `static/tab/home.jpg` |
| 1 | 智能体 | `pages/agent/agent` | `static/tab/agent.jpg` |
| 2 | 用户 | `pages/user/user` | `static/tab/user.jpg` |
| 3 | 课表 | `pages/timetable/timetable` | `static/tab/timetable.jpg` |

- 选中色 `#529bcc`；图标约 `iconWidth: 36px`，栏高约 `64px`
- **勿**把高清 `00.emoji` 原图直接配进原生 tabBar（易超 40KB 导致底栏消失）
- 改 `tabBar` / 新页面路由后需**整包重新运行**，热更新常不生效

## 5. 功能模块详解

### 5.1 首页（`pages/index`）

- 顶部 `<dailyDraw />`（每日签到）；常用/更多功能网格
- 外链分流：`openCampusWeb`（见 WebVPN）
- **无**冷启动遮罩 / 自定义首页加载图（相关资源与逻辑已删除）

### 5.1.1 WebVPN 网关（`pages/webvpn` + `utils/webvpn`）

解决「深链直接打开 → 内嵌多重跳转登录卡顿」：

1. 先打开 `https://webvpn.scut.edu.cn/`
2. 建议账号密码登录（扫码易失败）
3. 回到门户后自动进目标深链，或点「进入」
4. 企微 / 微信 scheme 外抛

`needsWebvpnGateway(url)`：仅 `*.webvpn.scut.edu.cn` 子站深链为 true。

课表导入 `import.vue` 复用同一套认证 URL 判断（`isAuthUrl` 等）。

### 5.2 每日签到（`components/dailyDraw`）

> 组件文件名仍为 `dailyDraw`（历史遗留），产品语义为「每日签到」，**已取消运势抽取**。

**未签到态**

- 文案：「每日签到」；两侧保留 🎡
- 样式：白底卡片；左右外侧天蓝色竖边（`border` 左右加粗），上下浅边；黑字标题

**签到流程**

1. 点击 → `uni.showLoading({ title: '签到中' })`
2. 从 `EMOJI_LIST`（00–15）随机一张，写入本地
3. 展示结果：上方人物 Emoji 图、下方对应配语、累计天数、「我的华工 · 签到的总是最好的」
4. 按自然日限制每天一次；当天再次进入从 storage 恢复同一张

**「今日已签到」判定（重要）**

- 必须同时满足：`daily_sign_last_date === 今天` **且** 存在合法 `daily_sign_emoji_v1`
- 仅有旧版运势留下的日期、没有新版 emoji 时：界面显示未签到，允许补签一次，且**不重复累加** `total_days`
- 旧键 `daily_sign_fortune` 已不再读写（可残留于设备，忽略即可）

### 5.3 用户页（`pages/user`）

- 顶部入口：**关于立绘** → `navigateTo('/pages/art/art')`（失败会弹窗提示重新运行）
- 联系我们 / 使用说明 / 一键反馈 / 鸣谢（说明与反馈仍支持单击 WebView、双击复制）

### 5.4 立绘鉴赏与 Emoji（`pages/art`、`pages/emoji` + `utils/artAssets` + `utils/useCardGallery`）

**立绘页（5 卡，左右滑动）**

1. **关于立绘**：`CREATION_STORY`（Markdown → `mdToHtml` + `rich-text`）；可纵向滚动阅读
2. **Emoji 表情包入口**（独立卡）：4×4 展示全部 16 张缩略图 +「进入 Emoji 表情包」按钮（网格与按钮在可用高度内垂直居中）→ `navigateTo('/pages/emoji/emoji')`
3. 半身像 `art-half.jpg`（`ART_IMAGES.half`）
4. 全身像 `art-full.jpg`（`ART_IMAGES.full`）
5. 草图 `art-sketch.jpg`（`ART_IMAGES.sketch`）

**Emoji 页**

- 图：`00.emoji/00.jpg`～`15.jpg` 共 16 张
- 配语：`EMOJI_CAPTIONS` / `EMOJI_LIST[].caption`（与图序号一一对应），展示在卡片图片下方
- 配语样式：约 `30rpx`、字重 `600`；`imageHeadRpx` 约 `400`，为多行配语留空

**翻页实现（高清 + 尽量不闪）**

- `useCardGallery`：所有卡片排在一条 `translate3d` 轨道上，跟手拖拽；**不**用原生 swiper 挂满大图
- 邻近页预挂载 / `getImageInfo` 预解码；切页不销毁当前可见 `<image>` 节点
- 立绘翻页时长默认 **500ms**；Emoji **400ms**（`animMs`）
- 卡片上下留白已加大，避免底部配语/署名被裁切
- 页面 `app-plus.bounce: none`
- `touchmove`：**仅横向跟手且 `cancelable` 时**再 `preventDefault`，避免控制台刷「Ignored attempt to cancel a touchmove…」；模板勿再用无条件 `.prevent`

### 5.5 课表（`pages/timetable` + `pages/import`）

**展示**：`local_course_data`、教学周、`semester_start`、`time_mode`（university / wushan）。

**导入（App）**：先 WebVPN 门户登录 →「进课表」打开教务课表 URL →「提取课表」注入脚本 → `app-import://` 回传 → 写入 storage。

#### 5.8.1 总体链路

```
agent.vue
  │  POST /chat
  │  body: { message, thread_id, device_context }
  ▼
00.my-agent（LangGraph ReAct + MiniMax + MemorySaver）
  │  工具：search_knowledge_base / open_campus_service / list_campus_services
  ▼
响应：{ thread_id, answer, actions[] }
  ▼
展示 answer；sanitize 后执行 actions（与首页按钮同路径）
```

- Base：`agentConfig.js` → `http://127.0.0.1:8000`（真机：`adb reverse tcp:8000 tcp:8000`；正式包同样可用，需 USB 调试而非仅传文件）
- 开源自建：`AGENT_SETUP_DOCS_URL` → `https://github.com/tuoxingwanli/SCUT-Helper-Agent`（配置 Key、装依赖、建向量库、一键启动、开发者模式 / USB / adb reverse）
- 超时 180s；`parseStreamParts` 处理 `<think>`；`mdToHtml` → `rich-text`
- 本地持久化：`agent_chat_messages_v1`（约 40 条，含 `plainText` / `thinkText` / 可选 `setupDocsUrl`）、`agent_thread_id_v1`
- 左滑全身像（同页层；图源 `ART_IMAGES.full`）
- **连不上后端**：错误气泡文案提示检查 8000 / adb reverse；下方可点「查看后端配置说明」并展示完整 GitHub URL，经 `openCampusWeb` 打开 WebView（`rich-text` 内 `<a>` 在 App 端不可靠，故用独立 `@tap` 区域）

#### 5.8.2 新对话与会话记忆

- 标题栏右侧 **「新对话」**：确认后清空气泡、换新 `thread_id`、清本地消息存储，并 `POST /chat/reset` 清理后端该旧线程的 `MemorySaver`
- 即便 reset 请求失败，新 `thread_id` 也不会再带上旧上下文
- 后端记忆：`MemorySaver` **进程内**、按 `thread_id` 累积；**未配置**固定「最近 N 轮 / token 上限」裁剪；进程重启即丢
- 前端 `MAX_STORE = 40` 只限制本地气泡展示条数，不限制后端记忆长度

#### 5.8.3 长按复制

- 长按**用户问题 / AI 正文** → 复制 `plainText`（Markdown 原文优先；旧缓存无字段则用 `htmlToPlain`）
- 长按**深度思考**区域 → 复制 `thinkText`
- `@longpress.stop`，并短暂抑制左滑全身像，避免误触

#### 5.8.4 阶段一：对话驱动跳转

**协议**：用户可见文案在 `answer`；机器指令在 `actions[]`（勿把 `NAVIGATE:` 当唯一通道）。

| action.type | 行为 | 示例 |
| --- | --- | --- |
| `switch_tab` | `uni.switchTab` | 首页签到、课表、用户页 |
| `navigate_to` | `uni.navigateTo` | 立绘、Emoji |
| `open_campus_web` | `openCampusWeb`（WebVPN 网关或普通 webview） | 查分、选课、教务、说明/反馈飞书链 |

**服务目录（前后端各一份，须对齐）**

- 后端：`00.my-agent/data/service_catalog.json`
- 前端白名单：`src/utils/serviceCatalog.js`
- 工具：`tools/app_actions.py` → `open_campus_service(service_key)`

**当前可跳转 key（节选）**：`home`（签到）、`timetable`、`art`、`emoji`、`contact`、`help`、`feedback`、`grade`、`gpa`、`course_select`、`jw_home`、`webvpn`、`ecourse`、`ecard`、`jw_office`、`cnki`、`wanfang`。

**防连环跳转**

- 后端 `_extract_actions`：只收集**本轮最后一条用户消息之后**的 ToolMessage（避免 MemorySaver 历史累积）
- 前端：新消息取消未执行定时器；同轮多条 actions **只执行最后一条**

**联调**：改 catalog / 工具后需**重启 Agent 后端**；真机无 `adb reverse` 会出现请求失败。

#### 5.8.5 阶段二：本地课表 + 当日签到上下文

课表数据在手机 `uni.storage`，**不爬教务**。前端 `agentContext.js` 按用户话术意图裁剪后随请求上传；后端 `device_context.py` 注入本轮提示，模型据此回答，**禁止编造**未列出的课程/签到。

| 用户说法（示例） | scope | 上传内容 |
| --- | --- | --- |
| 今天 / 今日有什么课 | `day` | 仅该日课程 |
| 明天 / 后天 / 前天 / 昨天… | `day` | 相对日课程 |
| 周三有什么课 | `day` | 本教学周该星期 |
| 下一节课 | `next` | 今日课 + 下一节 |
| 本周课表 | `week` | 本周按星期展开 |
| 整体 / 完整 / 全部课表 | `full` | 完整导入条目（含周次）+ 本周展开 |
| 签到了吗 / 配语 | `checkin` | 当日签到详情 |
| 打开课表 / 查分等纯跳转 | `none` | 几乎不传课表（减负） |

#### 5.8.7 已知局限（未改代码前知晓即可）

## 9. 设计与代码约定（现状）

1. 业务页多为 Vue 3 `<script setup>`；`webview` 仍为 Options API。
2. 主 Tab 只用 `switchTab`，禁止对 Tab 页 `reLaunch`（会整页销毁、底栏闪）。
3. WebVPN 类深链统一走网关页，勿直接 `webview` 开教务深链。
4. 立绘/Emoji 用原图 + `useCardGallery`，勿为顺滑而压糊鉴赏用图；tabBar 图标必须另存小图；**立绘静态资源文件名用 ASCII**（避免云打包裂图）。
5. Markdown（智能体回复、立绘创作说明）用自研 `mdToHtml`，避免 `marked` 在 App 白屏。
6. 每日签到与 Emoji 鉴赏共用 `EMOJI_LIST` / `EMOJI_CAPTIONS`，改配语只改 `artAssets.js`。
7. Agent 深链跳转统一 `openCampusWeb`（等同首页单击）；新增可跳转服务须同时改 `service_catalog.json` 与 `serviceCatalog.js`，并重启后端。
8. Agent 课表问答靠 `device_context` 意图裁剪，勿默认每次上传完整课表。
9. 应用图标必须用**真 PNG + 官方尺寸**；勿把 JPG 改后缀冒充 PNG。
10. 智能体消息持久化时保留 `plainText` / `thinkText`（及错误态 `setupDocsUrl`），便于长按复制与配置引导。
11. `.env` 含 API Key，勿提交；对外分享后端用 `.env.example` + 开源仓库 README。

# 初始架构

我现在不满足于做一个智能体，我想要做一个AI Agent 。就是比如，我说，我问今天有什么课？ 智能体能够调用工具查看我的课表然后告诉我今天什么课。再比如说，我说，我要查分，Agent自动跳转到那个页面。需要怎么完成？要求是在我手机上完成这些，手机上已经做出了一个鲤工助手软件，同时我现在真机调试也成功做出了智能体板块，可以正常对话的那种。



从“智能体”（Chatbot）升级到“AI Agent”（能调用工具执行任务），关键在于**给 Agent 装上“手”和“眼睛”** ——手用来调用接口/跳转页面，眼睛用来感知手机状态。

基于你已有 UniApp 的“鲤工助手”App + 正常对话的后端，下面是完整的升级方案。

------

## 一、整体架构思路

你的现有架构是：

text

```
手机 App → 后端 Agent（LangGraph）→ LLM → 返回文字回答
```



要升级为真正的 Agent，需要扩展为：

text

```
手机 App → 后端 Agent（LangGraph）→ LLM 决策 → 调用工具（Tools）
                                    ↓
                          工具执行后返回结果 → 继续对话/执行动作
```



**工具（Tools）** 就是 Agent 的“手”，可以分成三类：

| 类型               | 能力                 | 示例                         |
| :----------------- | :------------------- | :--------------------------- |
| **后端工具**       | 查数据库、调外部 API | 查课表、查成绩               |
| **手机端工具**     | 跳转页面、打开 App   | 跳转到查分页面、打开教务系统 |
| **GUI 自动化工具** | 模拟点击、滑动       | 自动登录、自动填表           |

------

## 二、具体实现方案（由简到难）

### 方案一：DeepLink/URL Scheme 跳转（最简单，推荐优先实现）

这是最轻量的方式。Agent 识别到用户意图后，返回一个 **DeepLink 链接**，App 接收后直接跳转到对应页面。

**实现步骤：**

**Step 1：在 UniApp 中配置 DeepLink 路由**

javascript

```
// App.vue 或 main.js 中配置
// 定义 URL Scheme 和路由映射
const routeMap = {
  '/grade': '/pages/grade/grade',        // 查分页面
  '/schedule': '/pages/schedule/schedule', // 课表页面
  '/course-select': '/pages/course/course-select', // 选课页面
  '/webvpn': '/pages/webvpn/webvpn',      // WebVPN 页面
  '/payment': '/pages/payment/payment'    // 缴费页面
}

// 监听 App 启动时的 URL Scheme
// 在 App 的 onLaunch 或 onShow 中处理
```



**Step 2：后端 Agent 增加“跳转工具”**

在 `agent.py` 中新增工具：

python

```
# tools/navigation.py
from langchain_core.tools import tool

@tool
def navigate_to_page(page_name: str) -> str:
    """
    跳转到 App 内的指定页面。
    page_name 可选值：'grade'（查分）、'schedule'（课表）、'course_select'（选课）、
    'webvpn'（WebVPN）、'payment'（缴费）
    """
    # 返回一个特殊标记，前端解析后执行跳转
    return f"NAVIGATE:{page_name}"
```



在 `agent.py` 中注册这个工具：

python

```
from tools.navigation import navigate_to_page

tools = [search_knowledge_base, navigate_to_page]  # 新增
```



**Step 3：App 端解析并执行跳转**

javascript

```
// 在对话页面处理回答
function handleAgentResponse(answer) {
  // 检查是否包含跳转指令
  if (answer.startsWith('NAVIGATE:')) {
    const page = answer.replace('NAVIGATE:', '');
    // 执行跳转
    uni.navigateTo({
      url: routeMap[page] || '/pages/index/index'
    });
    return;
  }
  // 否则正常显示文字回答
  this.replyText = answer;
}
```



**效果：** 用户说“我要查分”，Agent 返回 `NAVIGATE:grade`，App 自动跳转到查分页面。

### 方案二：调用后端 API 获取数据（查课表、查成绩等）

对于需要**获取实时数据**的任务（如查今天有什么课），Agent 需要调用后端接口查询数据库或教务系统。

**Step 1：后端新增数据查询工具**

python

```
# tools/schedule.py
from langchain_core.tools import tool
import requests

@tool
def get_today_schedule(student_id: str) -> str:
    """
    查询今日课表。需要学生学号。
    """
    # 调用教务系统 API 或查询本地数据库
    # 这里以调用教务 API 为例
    try:
        response = requests.get(
            f"https://your-api.com/schedule/{student_id}",
            headers={"Authorization": "Bearer YOUR_TOKEN"},
            timeout=10
        )
        if response.status_code == 200:
            data = response.json()
            courses = data.get("courses", [])
            if not courses:
                return "今天没有课哦，好好休息吧！"
            result = "📚 今天的课程：\n"
            for c in courses:
                result += f"- {c['time']} {c['name']} @ {c['room']}\n"
            return result
        return "暂时查不到课表，请稍后再试。"
    except Exception as e:
        return f"查询失败：{str(e)}"
```



**Step 2：注册工具**

python

```
from tools.schedule import get_today_schedule

tools = [search_knowledge_base, navigate_to_page, get_today_schedule]
```



**Step 3：App 端传递用户信息**

为了让 Agent 知道“你是谁”，需要在请求中带上用户标识（如学号）：

javascript

```
// 发送消息时带上用户信息
uni.request({
  url: BASE_URL + '/chat',
  method: 'POST',
  data: {
    message: userText,
    thread_id: threadId,
    user_id: '2024xxxxxx'  // 从登录状态获取学号
  }
});
```



后端接收后存入会话上下文，供工具调用时使用。

### 方案三：GUI 自动化操作手机（最强大，但也最复杂）

如果需要 Agent **真正像人一样操作手机**（比如自动打开教务系统、输入账号密码、点击查询按钮），就需要 GUI 自动化方案。

**主流方案：**

1. **智谱 AutoGLM-Phone**：开源手机端 Agent 框架，通过视觉语言模型理解屏幕内容，自动点击、滑动、输入。用户说“打开小红书搜美食”，它就能自动操作。
2. **AppFunctions（Android 官方）**：Google 推出的 AI 代理接口，让 Gemini 能自动执行日历、记事等应用任务。
3. **MCP 协议方案**：通过 Model Context Protocol 将手机能力暴露给 AI 应用。

**集成思路（以 AutoGLM 为例）：**

text

```
用户说“帮我查一下成绩”
    ↓
你的 Agent 判断需要操作教务系统
    ↓
调用 AutoGLM-Phone 的 API
    ↓
AutoGLM 通过 ADB 控制手机：打开浏览器 → 访问教务系统 → 输入账号密码 → 点击查询
    ↓
返回查询结果给用户
```



**但这需要额外的部署：**

- AutoGLM 需要运行在电脑或云端（通过 ADB 连接手机）
- 不适合纯本地手机 App 场景，更适合作为后端服务的一部分

## 三、推荐实施路线（针对你的场景）

考虑到你已经有 UniApp App 和可用的后端，建议按以下顺序推进：

### 第一阶段：DeepLink 跳转（1-2天完成）

- 在 UniApp 中配置好各页面的路由
- 后端增加 `navigate_to_page` 工具
- App 解析 `NAVIGATE:` 指令执行跳转

**可实现的场景：** “我要查分” → 跳转查分页；“我要选课” → 跳转选课页；“怎么缴费” → 跳转缴费页

### 第二阶段：数据查询工具（3-5天）

- 搭建课表/成绩查询 API（需要对接教务系统或本地数据库）
- 后端增加 `get_today_schedule`、`get_grade` 等工具
- App 传递用户身份信息

**可实现的场景：** “今天有什么课” → 返回课表列表；“我上学期绩点多少” → 返回绩点

### 第三阶段：GUI 自动化（可选，视需求复杂度而定）

- 如果只是校内系统跳转，DeepLink 已经足够
- 如果需要“自动帮我登录教务系统查成绩”，再考虑接入 AutoGLM

## 五、一句话总结

**最短路径**：先做 DeepLink 跳转（方案一），让 Agent 能“指哪打哪”——用户说查分就跳到查分页，说选课就跳到选课页。这是成本最低、见效最快的升级方式。数据查询类功能（方案二）可以后续逐步叠加，不影响已有功能。

你的后端 LangGraph 架构本身已经支持工具调用，只需要**新增工具定义 + App 端解析执行**两步，就能把“只会聊天的智能体”变成“能办事的 Agent”。
